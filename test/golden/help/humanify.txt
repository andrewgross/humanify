Unminify JavaScript using an OpenAI-compatible API

Usage: humanify [OPTIONS] <input>

Arguments:
  <input>  The input minified JavaScript file

Options:
      --endpoint <url>               OpenAI-compatible API endpoint (default: https://api.openai.com/v1). The API key is read from HUMANIFY_API_KEY (the environment or a .env file), never from a flag
  -m, --model <model>                Model identifier (default: gpt-4o-mini)
  -o, --output-dir <output>          Output directory (default: output)
  -v, --verbose...                   Increase verbosity (-v for info, -vv for debug)
  -c, --concurrency <n>              Max concurrent function-lane LLM requests (default: 50). Module-lane size is set separately via --module-concurrency; the global in-flight cap is their sum.
      --module-concurrency <n>       Max concurrent module-lane LLM requests (default: 40)
      --max-tokens <n>               Per-request completion token budget (default: 6000)
      --context-tokens <n>           Model context window in tokens; sizes the batched split-naming prompts (default: 32768, the local measurement model's window)
      --disable <passes>             Comma-separated pass switches to turn OFF for ablation (unknown names are fatal and list the valid set)
      --probe <probes>               Comma-separated instrumentation probes to turn ON (unknown names are fatal and list the valid set)
      --retries <n>                  Number of retry attempts for failed API calls (default: 3)
      --timeout <ms>                 LLM request timeout in milliseconds (default: 300000)
      --llm-cache <dir>              Cache LLM responses on disk keyed by request content. Repeated prompts become deterministic across sessions and reruns are nearly free — it also pins answers against a server whose replies drift between runs.
      --reasoning-effort <level>     Reasoning effort for reasoning models: low, medium, or high (default: server-side default). 'low' is ~8x faster on gpt-oss at equal name quality; only set it for reasoning models — non-reasoning models (e.g. gpt-4o-mini) reject it. [possible values: low, medium, high]
      --skip-libraries               Skip library code instead of processing it with the LLM (the default)
      --no-skip-libraries            Process library code with the LLM
      --log-file <path>              Write debug logs to file (implies -vv)
      --diagnostics <path>           Write detailed rename diagnostics to JSON file
      --library-index <dir>          Library fingerprint index for --diagnostics' libraryDiscovery (report-only: names, moves and renames nothing)
      --library-discovery-units      List every claimed, vetoed, library-class and queued unit in --diagnostics' libraryDiscovery (default: totals and packages)
      --stats-json <path>            Write the deterministic match/rename breakdown as compact JSON (coverage + transfer stats + prior-match counts) for the eval harness
      --dump-artifacts <dir>         Write the span-keyed decision-record dump to this directory (instrumentation). Inert by construction: the run's decisions are unchanged (proven by neutrality).
      --dump-asks <path>             Write the reason-labeled ask log (one JSONL row per LLM ask: scope, identifiers, wave/round, WHY it was asked) to this path. Recording only — no decision reads it; off unless passed.
      --bundler <type>               Force bundler type (webpack, browserify, rollup, esbuild, parcel, bun)
      --minifier <type>              Force minifier type (terser, esbuild, swc, bun, none)
      --batch-size <n>               Identifiers per LLM batch (default: 25)
      --max-retries <n>              Per-identifier LLM call limit, initial + retries (default: 2; further conflicts resolve by suffixing)
      --rename-retries <n>           Name-conflict re-ask limit: how many times a rejected rename suggestion may be re-asked, each retry disclosing every failed suggestion (default: 2). Independent of --max-retries — a barrier/sweep collision re-ask consumes this budget, not the in-window call limit
      --max-free-retries <n>         Cross-lane collision retry limit (default: 100)
      --lane-threshold <n>           Min bindings to enable parallel lanes (default: 25)
      --split                        Split output into a multi-file tree (src/ + vendor/ + run scaffold), emitted as a runnable CommonJS module graph by default
      --prior-version <path>         Path to a prior humanified file for cross-version rename reuse
      --no-reconcile-prior-diff      Disable the prior-diff reconcile pass (on by default with --prior-version: after generation, snap rename-noise diff hunks back to the prior version's names)
      --no-naming-floor              Disable the deterministic naming floor (on by default: closes minted-token coverage gaps by class/function-expression inner-id derivation + decoration retry)
      --no-naming-floor-sweep        Disable the LLM sweep of minted survivors (on by default: LLM-names the params/decls/vars the naming floor cannot derive; prior names transfer first)
      --split-ledger <path>          Prior split ledger for cross-release file-assignment inheritance (default: auto-discovered next to --prior-version)
      --split-pure                   Emit the byte-exact review tree instead of the runnable CommonJS module graph (the --split default). Requires --split
      --rename-ledger <dir>          Write a replayable rename ledger (every rename keyed by byte position) + source snapshot + a standalone apply.mjs, so the LLM-rename output can be reproduced without re-running the model
      --sequential                   The conservative naming schedule: the relaxed levers OFF (each naming window waits for the previous one and for its own shadowed-binding round), the byte-identical parallelization kept. The DEFAULT is the relaxed schedule (both levers on); --sequential ships the pre-2026-09-28 default's bytes at the same --batch-size — for debugging and comparison
      --simulate-llm-latency <path>  Instrument: price this run's LLM schedule with cold per-call latencies on a virtual clock and write the simulated LLM wall time to <path> (JSON)
      --perf-trace <path>            Write a performance trace to JSON file (Chrome Trace Event format, viewable at chrome://tracing or ui.perfetto.dev)
  -h, --help                         Print help
  -V, --version                      Print version
