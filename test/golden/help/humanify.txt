Unminify JavaScript using an OpenAI-compatible API

Usage: humanify [OPTIONS] <input>

Arguments:
  <input>  The input minified JavaScript file

Options:
      --config <file>              TOML config file: every setting that is not a flag (see humanify.example.toml for each key, its default and meaning). A flag that disagrees with the file is refused
  -o, --output-dir <output>        Output directory (default: output)
      --prior-version <path>       Path to a prior humanified file for cross-version rename reuse
      --endpoint <url>             OpenAI-compatible API endpoint (default: https://api.openai.com/v1). The API key is read from HUMANIFY_API_KEY (the environment or a .env file), never from a flag
  -m, --model <model>              Model identifier (default: gpt-4o-mini)
  -v, --verbose...                 Increase verbosity (-v for info, -vv for debug)
      --library-matching <mode>    Library matching: names (the default: library code the index recognises goes under vendor/<package>/ with its original names restored; needs a library index), report (the index lookup + graph discovery, reported; output as off), off (path/banner detection only; no index read, searched for or built)
      --library-index <dir|id>     The library fingerprint index (a directory, or an id under library.index_store; one with no slice for the bundle's kind fails the run). Without it, names/report use an index found in the library-index store for the bundle's kind (its packing tool) and skip library name matching, with one line, when it holds none; refused with off
      --library-index-store <dir>  The library-index store a run with no --library-index searches (library.index_store_dir; default .humanify/library-index, resolved against the working directory): one <id>/ per merged index, plus what --library-index-from-bundle builds with
      --library-index-from-bundle  When the store holds no index for the bundle's kind, build one at run time from the npm packages the bundle itself reveals (library banners, inlined package.json): installs each from the npm registry and bundles it with the recipe the bundle needs (Bun, esbuild, webpack or rollup; the pinned tool is fetched into the store's tools/), after printing the estimated disk and time (library.index_from_bundle)
  -h, --help                       Print help
  -V, --version                    Print version
