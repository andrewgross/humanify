### Rust spec (what the port must mirror)

- **The rule.** A function is library code iff its RAW start (offset into the
  file text the banners were found in, pre-beautify) lies in a banner region
  `[banner, nextBanner)` (the last region is open to EOF). Never compare a
  beautified offset with a region. Library functions: mark skipped `library`
  only if still pending (eval-taint keeps its reason), all join the prefix
  pass; nothing is classified when `skipLibraries` is off or a wrapper path
  was detected (unchanged).
- **While the Rust ingests TS-beautified text** (`--beautified-input`, phases
  1–5a) it has no raw starts, so it must CONSUME the classification: the TS
  dump's `regions.json.libraryFunctions` (`{key: fresh span in UTF-8 bytes,
sessionId, library}`, sorted by `key.start`) is the input and the parity
  view. Join by fresh span of the function node.
- **When the Rust owns beautify** (phase 5a): classify on the beautify
  transform's output tree while its function nodes still carry raw spans, in
  one shared pre-order walk (children in source/visitor order) over the
  Babel `Function` alias set (FunctionDeclaration, FunctionExpression,
  ArrowFunctionExpression, ObjectMethod, ClassMethod, ClassPrivateMethod);
  carry `(library|null, node type)` per ordinal; after re-parsing the printed
  text, the same walk must give the same count and per-ordinal type or fail
  loud. Do NOT re-derive order from raw text: flipComparisons reorders
  functions (a template literal moved after a call), which the ordinal over
  the OUTPUT tree handles and an ordinal over the raw tree would not.
- **Dump (#33).** `commentRegions[].span` is in the MINIFIED text (UTF-8
  bytes); an open end is `null`, never -1 and never converted. `regions.json`
  keys: `schemaVersion, commentRegions, libraryFunctions,
bannerClassifications` (`libraryFunctions: []` on the four eval pairs —
  the Bun detector never returns mixed files). The parity selftest literal
  in `humanify-parity/src/selftest.rs` needs the new key when the Rust
  writes regions.json.

### Rust wiring (2026-09-25, rust/library-freeze)

- **What runs.** `LibraryClassification::Consumed` (the TS dump's
  `libraryFunctions`, `--ts-library-functions <regions.json>` on the
  binary, read from the dump dir by the `naming` / `matches` /
  `transfers` verbs) joins onto the graph rows by fresh span; the freeze
  (`rename::transfer::library_freeze`) feeds the settle step, so the
  statement twins, the transfer stage, the waves and the prefix pass all
  read the same rows. A file with banner regions and no classification is
  `Missing` and fails loud when consulted (as the TS throws). The binary
  also proves the TS's `commentRegions` equal its own for the file before
  consuming.
- **5b.** `carry_function_libraries` / `resolve_function_libraries` over
  `place::babel_walk` (the one ESTree→babel walk; `Program` and the
  module declarations added to its VISITOR_KEYS table) are pinned to the
  real TS beautify on 15 vectors (test/parity/library-carry.json): the
  walk and the resolution match everywhere; the carry over an
  UNTRANSFORMED raw tree matches the TS output-tree carry on every vector
  but `reorder` — the proof the 5b lane must carry on the beautify output
  tree.
- **--split never co-occurs with the freeze today**: the stable split
  needs a bundle wrapper ("input is not stable-splittable") and a wrapper
  disables library detection.
- **The library-min "oddity" is not a freeze bug.** x1/x2 ship the
  prior's internals (`alphaRetries`) because the post-generate prior-diff
  reconcile (a text-level, freeze-blind pass, by design) snaps their
  `tinylib_` locals to the prior's names in its descriptive tier; x3 has
  no prior counterpart. library-freeze kept `tinylib_` only because its
  hand-written prior fails the reconcile's gates: its banner line sits
  inside the changed hunk (unequal hunk lengths) and, with the comments
  stripped, the prior is below the corpus-similarity gate (5 of 11 lines
  unchanged < 0.5). Padding the same case with 12 shared app lines
  (/work/lf/cases/library-freeze-snap) makes the TS snap the same 4
  bindings. A real humanify prior drops comments and was itself prefixed,
  so the snap is a no-op or a restore there. Both behaviours are
  reproduced byte for byte.

## Post-cutover levers (not bugs — parity forbids them until the TS is gone)

- **Parallel naming within a wave** (Andrew, 2026-09-26). Parity pins the
  TS's apply order at the wave barrier; after cutover only DETERMINISM is
  required. Across waves the order is a real data dependency (a caller's
  prompt shows its callees' new names); within a wave, independent members
  can be prompted, validated and staged in parallel and then applied in one
  canonical, input-derived order (the `core::par` pattern). Any order change
  moves output once — judge it with the eval (novel/realLn must not move).
- **AST-bound stages** stayed sequential because oxc nodes are not `Sync`
  (the close tier's per-pair rows, the AST serializations): restructure to
  extract plain data first, then parallelize.
