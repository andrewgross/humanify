## 2. The work-package loop

1. `git checkout rust-port && git pull --ff-only`; read `PORTING.md`'s header
   (oracle label in force) and pick a WP whose depends-on rows are
   parity-green and whose rows are unclaimed.
2. Claim: set the WP's rows `in-progress` with date + session in the gate-run
   column; commit that on `rust-port` directly (`git add PORTING.md`).
3. `git checkout -b rust/wp<id>-<slug>` off its stack parent.
4. Read the WP row's exit gate, the doc it cites, the TS files in the
   contents column and their `*.test.ts` LAST (the tests are the spec).
5. **Run the gate red.** For differ gates that means running
   `humanify-parity compare` against the oracle dump with the Rust side
   absent or stubbed and watching it report divergence. Save the log:
   `/work/rust-port/gates/<wp>/<date>-red.log`.
6. Port. Red/green per module. Free-form commits.
7. Gate green: same command, `/work/rust-port/gates/<wp>/<date>-green.log`.
8. `npm run check` bare. Read the summary. Then squash to a short series.
9. Merge `--no-ff` into `rust-port` with the citation format in
   `00-control.md` §5; update the WP's PORTING.md rows to `parity-green`
   IN THE SAME MERGE; push; tag `wp<id>-green`.
10. Dependents rebase onto the new `rust-port` and re-run their own gate
    (green does not survive a rebase).

## 3. Gate commands

| command                                                                  | what                                                                                                                                      | time      |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `npm run check`                                                          | THE gate, 11 stages: typecheck, lint, rust:fmt, rust:clippy, knip, knip:prod, census:clones (advisory), unit, rust:unit, fingerprint, e2e | ~35 s now |
| `npm run check -- --only rust:fmt,rust:clippy,rust:unit`                 | PARTIAL, labelled so; for iteration only                                                                                                  | seconds   |
| `cargo clippy --workspace --all-targets -- -D warnings`                  | what `rust:clippy` runs                                                                                                                   |           |
| `cargo test --workspace`                                                 | what `rust:unit` runs                                                                                                                     |           |
| `cargo run -p humanify-parity -- <verb> ...`                             | the differ (from WP0.3)                                                                                                                   |           |
| `npm run eval -- neutrality <ref> [pair] --cache /work/neutrality-cache` | byte-identity, WARM only; read the baseline leg's cache-write count BEFORE the verdict line                                               | ~25 min   |
| `npm run eval -- score <label>`                                          | cold 4-pair eval; not a parity-era instrument (used at 5b)                                                                                | ~1 h      |

Cargo's binaries in the gate resolve through PATH; the container's
`~/.profile` and `~/.bashrc` export `~/.cargo/bin`. A shell that lacks it
fails `rust:*` loudly with "cargo: not found", which is correct — a gate
that cannot run must not pass.

## 4. Long-run hygiene

- Freeze first: `git worktree add --detach /work/<label>-frozen <sha>`;
  runs execute a frozen tree, never the live one (a half-edited tree ran an
  experiment once).
- `nohup <cmd> > /work/<name>.out 2>&1 &` and watch with a background
  until-loop; never a blocking sleep. Include an error-storm tripwire
  (`grep -ac 'Connection error'`) in any watcher on an LLM run.
- `src/` is not edited while a neutrality candidate leg runs.
- Heap: `--heap-mb 65536` is the default; 14 GB OOMs cold on 215→216.
- Every result that changes a number in a doc gets a dated note in that doc
  the same day (rule 9).

## 5. Probes (risk register 11 §1)

Each probe's result is written into its row of `11-risk-register.md` with
the date. Runnable before phase 0.

**R14 — the parity loop is server-free (run 2026-09-19: PASSED).**
Warm neutrality with the endpoint pointed at a dead port. Success with the
baseline leg at +0 cache writes proves replay never touches the model.

```bash
export PATH="$HOME/.bun/bin:$PATH"
nohup experiments/lib/neutrality.sh <baseline-sha> 2.1.85:2.1.86 \
  --cache /work/neutrality-cache --endpoint http://127.0.0.1:9 > /work/r14-probe.out 2>&1 &
# read: "cache writes" for BOTH legs, then the verdict. Baseline +0 is the precondition.
```

**RESULT 2026-09-19: PASSED.** `neutrality.sh fd3ac32 2.1.85:2.1.86 --cache /work/neutrality-cache --endpoint http://127.0.0.1:9` — candidate leg (208ead0) +0 cache writes, baseline leg (fd3ac32) +0, exit 0 both, 0 differing files / 0 lines, zero connection errors with the endpoint dead. Two facts: the warm-replay loop never touches the model, and the standing cache is warm for current `main`. Log: `/work/r14-probe.out`.

## 6. Oracle freeze (WP0.4)

Precondition: WP0.2 merged and proven inert; `00-control.md` §4.1 decided.

```bash
SHA=$(git rev-parse --short HEAD); LABEL=oracle-$SHA; O=/work/oracle/$LABEL
git worktree add --detach /work/$LABEL-frozen $SHA      # symlink node_modules + fixtures (§1)
mkdir -p $O/dumps $O/cache
# per pair, warm (the standing cache) so every prompt replays:
#   <pipeline> <fresh> --prior-version <prior> --llm-cache /work/neutrality-cache \
#     --dump-artifacts $O/dumps/<from>-<to> ...   (exact flags = 14-pipeline-contract.md)
# fixture set: the e2e fixtures under test/e2e/fixtures, dumps under $O/dumps/fixtures/
tar -C /work -czf $O/cache/neutrality-cache-$SHA.tgz neutrality-cache
(cd $O && find . -type f ! -name MANIFEST.sha256 -print0 | sort -z | xargs -0 sha256sum > MANIFEST.sha256)
```

Then: `PORTING.md` header gets the label and commit; every later gate cites
the label; a re-dump (after any decision-changing `src/` merge) makes a NEW
label and marks every `parity-green` row citing the old one stale.

## 7. Neutrality recipes

Standard (two commits, warm): `npm run eval -- neutrality <baseline-sha> [from:to] --cache /work/neutrality-cache`.
Valid only warm; the baseline leg's write count must be 0; a cold run is
meaningless (CLAUDE.md, proven by a null control).

Per-leg command (needed by WP0.2's flag-on/off proof and by phase 5a):
`neutrality.sh` refuses same-commit comparisons today. WP0.2 adds
`--candidate-cmd '<cmd>'` and `--baseline-cmd '<cmd>'` (each a full
pipeline invocation template) so one commit can be compared with itself
under two flag sets, and later a Rust binary against the TS pipeline. The
write-count precondition and the verdict logic are unchanged. This
extension is harness-side TypeScript/shell, not `src/`, and is itself
proven with a self-vs-self run that must report 0 files / 0 lines.

## 8. Recording results

- Gate logs: `/work/rust-port/gates/<wp>/<date>-{red,green}.log`.
- Hand-back notes: `/work/rust-port/handback/<checkpoint>-<date>.md`.

  PORTING.md gate-run column, in the same commit as the status change.
- Doc upkeep: the owning doc, in place, dated note, same day.

## 9. Known traps

- Fresh worktree has no fixtures or node_modules (§1 recipe).
- `~/.ssh/known_hosts` was wiped by a container re-init once (2026-09-18);
  `ssh-keyscan -t ed25519,ecdsa,rsa github.com` and verify fingerprints
  against GitHub's published ones before appending.
- The `-vv` log records every LLM call twice (full block + compact block);
  dedupe per binding in any census.
- `npm run check | tail` returns tail's exit code. Never pipe the gate.
- A green gate on a rebased branch is a new claim; re-run it.
