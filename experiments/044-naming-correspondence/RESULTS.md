# 044 — Task A: most of "naming" noise is not naming

Brief: [README.md](README.md). Jargon: [034 vocabulary](../034-eval-harness/VOCABULARY.md).

**Status: Task A COMPLETE, and it redirects the experiment. The correspondence
hypothesis this brief was written to test is NOT the main story. 38% of all
naming churn — 2,966 of 7,816 git lines — is IMPORT-ALIAS churn generated by the
SPLIT stage from file paths, never by the renamer. No `src/` change yet.**

## The attribution gap, diagnosed rather than patched

The census left 50–86% of lines `unattributed`. The brief made closing it task
A.1 on the assumption it was a join bug. It is not:

| cause          | 85→86 |
| -------------- | ----: |
| not-in-trail   | 3,368 |
| ambiguous-name |    58 |

The join was hardened anyway — only `applied` trail entries count, and a name
settled by two different tiers in two scopes is marked `AMBIGUOUS` rather than
silently taking the first (9,434 of 58,522 applied names repeat on 85→86). That
moved 58 substitutions. The other 3,368 are **not in the renamer's trail at
all**, and the samples say why:

    skillFiles             -> apiResponseSkillFiles
    loggerDebugLogger      -> sessionLoggerEventLogger
    lspSearchSearchResults -> statusMessage
    commandRunner          -> socketManager

`lsp-search/search-results.js`, `session-logger/event-logger.js`,
`status-message.js`, `command-runner.js` — those are **file paths**. These
identifiers are import aliases the split generates from the target path. The
renamer never sees them, so no trail entry exists. The instrument was right; the
model of what lives in the naming bucket was wrong.

## Read first, per the standing rule

    prior:  const skillFiles            = require("../../agent/api-response/skill-files.js");
    fresh:  const apiResponseSkillFiles = require("../../agent/api-response/skill-files.js");

The require **path is byte-identical**. Only the local alias changed — a bare
stem became folder-qualified — and every usage site in the file moved with it
(`(0, apiResponseSkillFiles.initializeFileSystemRef)()`, twice in this file
alone), across every file that imports it.

## TOTAL — import-alias churn, measured in git lines

| hop     | naming churn | same import, re-aliased | import path changed | **alias total** |     share |
| ------- | -----------: | ----------------------: | ------------------: | --------------: | --------: |
| 85→86   |        5,788 |                      40 |           **2,008** |       **2,048** |     35.4% |
| 118→119 |          506 |                 **212** |                  21 |         **233** |     46.0% |
| 197→198 |          718 |                      46 |                 102 |         **148** |     20.6% |
| 215→216 |          804 |                 **253** |             **284** |         **537** |     66.8% |
| TOTAL   |    **7,816** |                 **551** |           **2,415** |       **2,966** | **38.0%** |

Two distinct mechanisms, both mechanical:

- **Same import, re-aliased** (551 ln) — the path did not change; the alias
  generator picked a different qualification level. A pure defect.
- **Import path changed** (2,415 ln) — the imported FILE moved or was renamed
  (`command-runner.js` → `socket-manager.js`, `markdown-renderer.js` →
  `language-detector.js`, `config-loader.js` → `lsp-service.js`), so its
  path-derived alias changed in every importer. Placement and file-stem churn
  propagating into the naming bucket.

A third shape appears only on 197→198: `lib_e78a0486 → lib_25eac7e7` for
`vendor/kubernetes-client.js` — vendor aliases carrying a CONTENT HASH, which
churns whenever the vendored file changes at all.

## The finding that redirects the experiment

exp039 identified a "6+ substitutions, genuine drift" slice as the hard core —
32% of its noiseLn, and on exp043's trees 3,874 git lines, **67% of 85→86**. The
brief above proposed that this was two matchers disagreeing about correspondence.

It is not. Of those 3,874 lines, **3,620 (93.4%) are statements whose
substitutions include import aliases**:

    6+ substitution statements (412 / 3,874 ln):
      every substitution an alias    0 ln
      SOME substitution an alias  3,620 ln
      no alias substitution         254 ln

A statement that references six imported modules whose aliases all changed does
not represent six names drifting. It is one cause, counted six times, and the
statement re-prints in full.

That is why "6+ substitutions" looked like irreducible drift and why attribution
looked broken: both are the same artifact of measuring a split-stage naming
mechanism with a rename-stage instrument.

## What this means for the plan

**Task B changes.** The candidate is no longer a correspondence tiebreak on the
naming side. It is import-alias stability, which is the same "prior wins"
principle every other tier in this codebase already uses:

> An import alias is a purely LOCAL name whose only job is to reference a
> module. It has no reason to change when the module's file is renamed, as long
> as it is the same module. Inherit the prior release's alias when the importing
> file and the imported module both carry over.

Ceiling: **2,966 git lines, 38% of naming noise**, and it is the leading
component on three of the four hops (46% / 21% / 67%), with 85→86's 2,048 lines
the largest single block. It needs no LLM, no matcher change, and no new
evidence — the split already knows both the prior ledger and the target module.

Honest caveat on the ceiling: it is share-weighted (a statement with six
substitutions of which five are aliases contributes 5/6 of its lines), so
removing alias churn does not delete those statements from the diff — it only
removes the alias share. Statements with a real rename alongside will still
print. The 2,966 is therefore an upper bound on this lever, and the residue
after it is the honest size of the correspondence question.

## Also worth fixing: the `alias` metric understates itself by 15×

`diff-composition.ts` classifies a statement as `alias` churn only when it is a
`const x = require("...")` declaration. That counts the import HEADER lines —
200 git lines across four hops — while every USAGE SITE of the same re-aliased
import sits inside an ordinary statement and is charged to `naming`. The true
cost of alias instability is 2,966, not 200. Any future ranking that reads the
`alias` column at face value will rank this lever last when it is first.

## Still open from Task A

Reading the ten largest 6+ substitution statements is no longer the priority

NO alias involvement, which is the only surviving evidence for the original
