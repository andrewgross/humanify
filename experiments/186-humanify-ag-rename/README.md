## What changed

- **Crates.** `crates/humanify-X` → `crates/humanify-ag-X` by `git mv`; package
  names `humanify-ag-X`, Rust paths `humanify_ag_X::`. Every `use`/path in the
  workspace was rewritten mechanically (a `humanify_core` → `humanify_ag_core`
  substitution, and the same for the other four). In
  `crates/humanify-ag-index/src/{spec,planner,asof}.rs` (which exp187 edits)
  the ONLY changes are those path substitutions plus one doc-comment command
  spelling in spec.rs; a rebase resolves by re-applying the substitution.
- **One binary.** `crates/humanify-ag-cli` builds `humanify-ag`. The index
  crate has no `[[bin]]` any more: its old `main.rs` is now
  `crates/humanify-ag-index/src/cli.rs` (`IndexCommand`, `run_index`), and
  `humanify-ag` dispatches `index` to it like any other verb. Flags, output,
  exit codes and the allocator (mimalloc, now the one binary's) are unchanged;
  the allocator test moved with the allocator (`crates/humanify-ag-cli/src/allocator_test.rs`).
  New test: `the_index_builder_is_a_subcommand` (every old flag parses, none
  dropped, the required ones still required).
  - `humanify-index build --spec …` → `humanify-ag index build --spec …`
  - `humanify-index slim-cache …` → `humanify-ag index slim-cache …`
  - the pipeline is still the bare command: `humanify-ag <input> [options]`;
    the stage verbs are `humanify-ag detect|unpack|discover|format|format-check|match`.
- **Per-commit binary name.** `experiments/lib/build-bin.sh` now reads the
  pipeline's crate and binary off the checkout (`pipeline_crate_of`):
  `humanify-ag-cli`/`humanify-ag` when `crates/humanify-ag-cli` exists,
  `humanify-cli`/`humanify` before the rename, a FATAL otherwise. A
  neutrality baseline at a pre-rename commit builds and runs `humanify`.
  Tested red→green (`experiments/lib/build-bin.test.ts`, fake cargo, both
  layouts + neither). `experiments/096-library-matching-score/run.py` (which
  also builds the binary at a commit) calls the same function rather than
  re-deriving it; `docs/responsibility.md` has the row.
- **Launch sites** (binary path, `cargo -p`, subcommand): `scripts/check.ts`
  (rust:build), `scripts/e2e.ts`, `scripts/format-golden.sh`,
  `scripts/ask-trace.ts`, `scripts/eval.ts` (`--bin` default),
  `scripts/build-index.sh` (now `cargo build -p humanify-ag-cli` and
  `humanify-ag index build`), `experiments/lib/build-bin.sh`,
  `experiments/lib/pipeline-bin.ts`, `experiments/lib/detect-census.ts`,
  `experiments/lib/match-truth/run.ts`,
  `experiments/096-library-matching-score/run.py`,
  `experiments/034-eval-harness/run-launch.test.ts`,
  `test/eval-score-args.test.ts`, and the ten `CARGO_BIN_EXE_humanify` sites
  in `crates/humanify-ag-cli/tests/`. Plus every file path the harness keeps
  (`scripts/concurrency-allowlist.json`, `.prettierignore`, `clippy.toml`).
- **Goldens, regenerated by their generators:** `test/golden/help/humanify-ag.txt`
  and `humanify-ag-short.txt` (renamed from `humanify.txt` / `humanify-short.txt`;
  `humanify-ag --help`, `humanify-ag -h`), `test/golden/help/match.txt`
  (`humanify-ag match --help`), `humanify.example.toml`
  (`cargo test -p humanify-ag-cli write_the_example_config -- --ignored`).
  Each diff is the program name only.
- **package.json** name `humanifyjs` → `humanify-ag` (and package-lock.json's
  two copies of it). Version unchanged (2.2.2; `--version` reads it).
- **Docs.** README (title, usage, layout, the index builder), docs/\* crate
  paths and command spellings, `docs/design/library-index.md`'s "where it
  lives". Experiment READMEs/RESULTS are historical and were NOT edited;
  experiment scripts outside the harness directories named in the brief
  (exp095/097/101/105/131/… build scripts and Rust protos that point at
  `crates/humanify-index` or a `humanify-index` binary) were left as the
  historical records they are — they no longer build/run against this tree.
  `docs/rust-port/` got crate PATH updates only (so its links resolve); its
  command spellings are history and were left.
