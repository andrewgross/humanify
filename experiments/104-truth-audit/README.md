## What changed: three mechanical rules

None of the rules reads the scored claims. Each one applies to every corpus entry the same way, and each was
designed on dev only.

### 1. `carried`: a unit the source map never mapped is `<unmapped>` (truth_audit.py)

The truth credits each generated byte to the last mapping before it, because a segment runs until the next one.
When a bundler emits no mapping for some code, that code is credited to whatever mapping came before it:

- Bun maps no JSON module. Lighthouse's own locale tables (13.7 MB, 9.4 MB of it counted as library) were
  credited to a 978-byte `@paulirish/trace_engine` file and to one of lighthouse's own files.
- get-east-asian-width's lookup tables, yoctocolors, ansi-escapes and `environment` were credited to `ora` or
  `marked-terminal`. These are "ora's and marked-terminal's dependencies" in exp102's list.

The rule: a statement unit with **no mapping segment starting inside it** is `<unmapped>` when its identifier
and number tokens are mostly **absent from the source it was carried from**. "Mostly absent" means that fewer than
50% of the tokens are present, counting only tokens that some map source contains and requiring at least 3 of them.
The rule reads only the frozen bundle, map and truth. It needs no index and no claims.

### 2. `copies`: vendored copies with no marker (copies.py -> copies.json / copies-test.json)

origins.py sees only markers and vendored directories. A unit labelled shipper S@v gets the origin O when all of
these hold:

- **code:** O's family's index prints cover at least 50% of the unit. A print that more than 3 families hold is
  shared helper code and does not count.
- **dependency:** S@v's own npm manifest declares O, or a package linked to O. Plain same-scope does not count.
  This test is what separates an origin from a consumer.
- **named:** S's shipped file names O, for example in a license banner, a comment or a kept path.
- **unique:** exactly one origin passes.

The layer is frozen as byte ranges, built from one reference label (`step4f-structural`, or
`test-step4f-structural` for test) and one index (step4).

The `named` test was added after the first run on dev, which showed openai's internal tslib helper matching zod and
@google/genai matching prettier's bundled index row. Dev results: 617 KB of units match code; 584 KB of that has no
declared dependency; **30.7 KB are copies** (tweetnacl and fflate in openpgp, lodash in cytoscape, and
micromark-util-edit-map in micromark-extension-gfm-table).

### 3. `family`: families joined by npm metadata (derive_families.py -> families-derived.json, families_lib.py)

Over 10,530 package names (those the truths, origins and reports mention, plus the dependencies their shippers
declare), three kinds of link:

- **repo:** two packages share one repository. 433 repositories hold more than one package.
- **rename:** a `deprecated` message says "renamed to / moved to X". 43 links, e.g. mimic-fn -> mimic-function.
- **fork:** `@x/N` and `N` have the same repository name AND GitHub records `@x/N`'s repository as a fork of
  N's. 35 links.

The fork rule needs the GitHub check. Name equality alone linked unrelated code (`is` / `@sindresorhus/is`,
`uuid` / `@lukeed/uuid`, `once` / `@tootallnate/once`). The check also re-derives only 1 of the 5 hand-listed
`scopedForks`; those stay as given.

npm's security placeholders are skipped. The judgement is **pairwise** (families.json's family OR linked). Folding
the links into scope families transitively chained unrelated packages: tweetnacl ~ @openpgp/* ~ jsdoc.

**One scope of the family notion is project-level.** Like the existing same-scope rule, `inquirer` is judged right
on `@inquirer/ansi` code. The hand-check marks the 2 such draws.

## Not relabelled, and why (exp102's list)

- **zod-to-json-schema in @ai-sdk/provider-utils:** copied as source, and provider-utils does not declare it. It
  stays wrong. The scorer cannot tell this from a matcher error without a per-package rule.
- **noble-curves in openpgp:** the matcher named `noble-curves` from a license banner, and no npm package has that
  name (`@noble/curves` does). This is a matcher follow-up: resolve banner names to npm names.
- **quickjs-wasi in puppeteer-core:** the unit is TypeScript's `__disposeResources` helper, so this is a real
  matcher error. exp102 had listed it as a copy.
- **got / @sindresorhus/is, sharp / semver, camelcase / ansi-align:** a consumer named for its dependency, or the
  other way round. These are matcher errors and stay wrong.

### App code claimed on test (diagnosis; aggregates only)

- **test-esbuild, 13,806 B: a TRUTH ARTIFACT, plus a real wrong-family claim.** All of these bytes map to TypeScript
  sources under `<app>/bin/packages/compiler/src/...`. esbuild CHAINED a package's own source map: Angular's
  compiler ships `fesm2022/*.mjs.map` with `../../../../packages/...` sources, and resolving those against the
  package file escapes `node_modules`. The truth then calls the result app code. The code is `@angular/compiler`.
  The claim, `@mixmark-io/domino` (one index seed of 480 B, then propagation), is still WRONG under a correct
  truth, so these bytes should count as wrong-family, not as app code.
  - Truth fix (corpus.py): a chained source should keep the package of the file that referenced the map, or at
    least never be `<app>` when its path does not exist in the app's tree.
  - Matcher side: reproduce on dev with the held-out angular entries (`@mixmark-io/domino <- @angular/compiler`,
    591 B in exp102's residual).
- **test-rollup, 76 B (agreement 72 B): bundler GLUE.** Two statements (`entryExports=requireEntry$2()` and the
  `getDefaultExportFromCjs` call) are mapped to the virtual id `entry.cjs?commonjs-entry` of rollup's CommonJS
  plugin, which resolves to an app path. MODULE propagation claimed them for the library the glue requires.
  - Truth fix: a `?commonjs-*` virtual id is bundler-generated and should be `<unmapped>`, like exp100's `\0` rule.
  - Matcher side: MODULE propagation should not cross into rollup's commonjs proxy statements.

## Matcher and scorer: one family definition?

The Rust matcher (`libindex/families.rs`) and the scorer (`libix.family`) read the SAME `families.json`.
Scorer 4 adds the derived links on the scorer side only. Feeding `families-derived.json` to the matcher's
isolation veto changes claims, which needs a label run and a neutrality check. That is a follow-up lane, not done
here. Until it lands, the matcher's family is a subset of the scorer's, which errs toward conservative claims.

The miss classifier (decompose.py) keeps the matcher's families. It explains why the MATCHER missed.
